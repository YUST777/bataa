# Course Path, Progress, and Retention

## Course path hierarchy

Use a hierarchy that maps to real capability:

`Course -> Unit -> Lesson -> Task -> Attempt`

- A course answers: what can I learn?
- A unit answers: what capability am I building now?
- A lesson answers: what small outcome will I complete today?
- A task answers: what must I do on this screen?
- An attempt records evidence, hints, and correction.

## Path screen rules

- Show the current unit title and capability in plain language.
- Make the next lesson the strongest item on the screen.
- Distinguish `locked`, `available`, `in progress`, `completed`, and `mastered` using shape, icon, label, and color.
- Let the learner revisit completed lessons.
- Explain prerequisites when a lesson is locked.
- Keep future content visible enough to create direction but not so dense that it overwhelms.
- Pin a compact daily goal or progress summary without competing with the next lesson CTA.

The path may curve or use nodes, but geometry is secondary to readable labels and state clarity.

## Progress model

Track distinct signals instead of collapsing everything into XP:

- Course completion percentage.
- Concepts introduced.
- Concepts practiced successfully after a delay.
- Projects completed.
- Mistakes awaiting review.
- Sustainable learning days.

XP may reward effort, but it must not imply mastery.

## Gentle streak system

- Count a day when the learner completes one meaningful lesson or review.
- Offer one chosen weekly rest day.
- Provide recovery through a short review, not a paid or scarce freeze item.
- Use factual reminders: `Your 10-minute lesson is ready.`
- Never use emotional manipulation from the mascot.
- Allow reminders to be scheduled, muted, and disabled.
- Treat a broken streak as a new start, not a failure screen.

## Daily loop

1. Show the next lesson and estimated time.
2. Remind the learner of the real-world outcome.
3. Complete a short task sequence.
4. Show the built result and concise learning summary.
5. Offer review only when it adds learning value.
6. Preview the next lesson to preserve momentum.

## Reward hierarchy

Reward in this order:

1. Visible artifact or working output.
2. Capability statement: `You can now style a button's states.`
3. Course-path progress.
4. Mistakes resolved or concept strengthened.
5. Streak and XP.

Keep celebration brief enough that returning to the path feels immediate.

## Day 1 path node

**Title:** Build your first button  
**Outcome:** Create a semantic HTML button with a clear label and basic CSS styling.  
**Duration:** 8–10 minutes.  
**Prerequisite:** None.  
**Evidence:** The preview contains a keyboard-focusable `<button>` labeled `Start learning` with the required background, text contrast, padding, and border radius.  
**Next lesson preview:** Add hover and focus states.

## Avoid retention traps

- Do not gate learning with finite hearts.
- Do not rank beginners against power users by raw activity.
- Do not inflate notification frequency after a missed day.
- Do not make social competition mandatory.
- Do not hide core mistake review behind payment.
- Do not reward repeated trivial exercises more than meaningful projects.
